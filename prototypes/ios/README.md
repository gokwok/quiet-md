# Quiet.md iOS 原型

原型锁定 `gpui-pre`、`gpui-pre-platform` 和 `gpui-pre-ios` 的 0.3.12。构建脚本把当前桌面源码复制到 `target/ios/stage`，再应用 [GPUI 适配补丁](port.patch)，直接编译整个桌面应用：`Workspace`、文档库、主页、侧栏、搜索、回收站、设置和编辑器都是同一份代码，并通过路径依赖共用 `fdl_core`。桌面 Cargo workspace 继续使用自己的依赖清单。

iOS 自己的代码在本目录，补丁里只留挂接点：

| 文件 | 内容 |
|---|---|
| `app.rs` | 入口（`crate::ios`）；手机版式的判断、安全区、抽屉、长按当右键、左缘返回 |
| `files.rs` | 系统的文件选择器（`UIDocumentPickerViewController`）：选文件、选文件夹、把写好的文件存出去 |
| `glass.rs` | 原生 Liquid Glass：把 `UIGlassEffect` 的视图盖在 GPUI 画面之上，和 GPUI 元素对位 |
| `shot.rs` | 退场：换页、收面板时用原生快照留住旧的样子，交给 Core Animation 送走；玻璃所在的那一层 |
| `keybar.rs` | 键盘上方的工具条 |
| `menu.rs` | 系统的弹出菜单：在 GPUI 元素的位置盖一个透明的原生按钮，挂上 `UIMenu`，菜单项被点后回到工作区 |
| `editmenu.rs` | 系统的编辑菜单（`UIEditMenuInteraction`）：对着选区弹出，项被点后回到编辑器 |
| `touch.rs` | 什么时候出编辑菜单、里面有哪几项；块右侧的拖动标记和长按提起整块（作为 `editor` 的子模块编译） |
| `port.patch` | 上游 GPUI 的 API 差异，加上各处的手机版式分支 |

## 手机上的界面

宽度小于 700pt 时是单栏版式。更宽时走桌面的两栏版式，但 `Info.plist` 还没有声明 iPad，这条分支没有在设备上跑过：

- **按手机的习惯，不是缩小的桌面。** 主页和文档页都没有实心的顶栏：内容顶到屏幕上沿，从悬浮的圆钮和状态栏下面滚过（状态栏下有一道渐隐）。主页和文件夹页是窗口的浅灰底上浮着白色的卡片，页名是大标题，和工具行一起跟着内容滚走；顶上右边是新建文件夹（文件夹页左边是回上一级），卡片一直铺到屏幕下沿。文档页只有返回、目录和「…」三个圆钮。打字时文档页右上角换成一个主色的「完成」，点了收起键盘。批量管理时和列表为空时，主页和文件夹页回到固定的标题栏。外壳的菜单（长按卡片或行、文档的「…」）从底部升起成动作面板，占满屏宽，下面压暗。菜单行和侧栏行 44pt，按钮 42pt，字号 16pt。手指抬起后不留悬停高亮。
- **首页是几个去处，不是文档库的平铺。** 大标题下依次是搜索、收藏（横向排开的卡片，没有时是一块提示）、「所有文档」、「文件夹」一栏（顶层的文件夹，带项数）和最近打开的几篇。首页顶上没有按钮：「文件夹」一栏右边的「…」弹出系统自己的菜单（`UIMenu`），里面是新建文件夹和折叠 / 展开这一栏；折叠只在这次运行里记着。
- **浏览页是同一套。** 「所有文档」（整个文档库里所有文档的平铺，不分层，不含文件夹）、「文件夹」（点首页那一栏的标题进，顶层的文件夹）和某个文件夹里，三页长得一样：左上返回，右上「选择」和「…」，大标题和一条搜索跟着内容滚走，下面是原来的网格 / 列表。「…」是一颗系统的玻璃钮，挂着系统菜单，分三组：新建文件夹（所有文档里没有）、宫格 / 列表、排序，当前的那项打勾。「选择」进批量管理，顶上换成一行固定的工具条：全选、已选几项、创建副本、移动到、删除、完成。
- **重命名在一张卡片里。** 手机上没有侧栏，新建文件夹和菜单里的「重命名」在屏幕上方弹出一张卡片，回车或点别处保存。
- **文件夹的图标可以换。** 长按文件夹，菜单里「更改图标」打开一组 emoji；选的图标记在文档库索引里（`Meta::folder_icon`，核心库的新字段），首页的文件夹行、文件夹页的标题和搜索结果都用它。桌面版还没有这个入口，也还不在文件夹卡片和侧栏上显示。
- **底部标签栏是主导航，不是侧栏。** 主页、回收站、设置排在底部的一条玻璃上，当前页那格垫着底色；右边是单独的新建按钮。搜索是首页、所有文档和文件夹页大标题下面的那一条，不在标签栏里。主页、文件夹、回收站和设置页都有它。主页不再拉抽屉（文档树和主页的卡片是同一份内容）。
- **设置是两级，不用侧栏。** 第一级是「设置」大标题下的一组分类（通用、外观、文档库、关于），带标签栏；点进去是那一类的设置，左上角玻璃的返回、页名居中，没有标签栏。左缘右滑从第二级回第一级。回收站是标签栏上单独的一页，它左上角的侧栏按钮还在。
- **Liquid Glass。** iOS 26 起，上面这些悬浮的按钮（标签栏、新建、返回、目录、「…」）是系统的玻璃，折射的是下面滚过的内容，按下会缩一下；长按出菜单和点新建有触感反馈。玻璃跟应用自己的深浅色。更早的系统没有这个效果：仍是原来的实心顶栏、抽屉、标题下的搜索条和纯色的新建按钮。见下面「原生玻璃」。
- **编辑器的块菜单和添加面板也是底部面板。** 块菜单占满屏宽，类型图标六个一行、每格 44pt；「缩进和对齐」「颜色」点开后是叠在块菜单上面的另一张卡片，顶上一行返回，点块菜单露出的部分或面板外面都只收起这一层；添加面板贴在键盘工具条上方。面板出现时从下面升上来，最高只到悬浮的那排按钮下面；收起时滑出屏幕下沿。添加面板里「表格」「分栏」的尺寸选择器占满屏宽，点哪格就插入那么大的。
- **过渡。** 进文档、进文件夹（包括子文件夹）、首页的子页、设置的第二级：新页从右边滑入并淡入。返回时离开的那一页向右滑出（左边一道阴影），下面那一页带视差从左边回来、压着的一层暗渐渐褪去；标签栏不动，只属于新页的玻璃等旧页走完再淡入。文档、文件夹、首页的子页和设置的第二级可以从左缘右滑跟手返回：松手过半（或往右甩）就滑走，不过半就滑回来、恢复原来那页（文档回来时键盘不会再弹出）。标签页之间只淡入。底部面板（外壳的动作面板、块菜单和它的子面板、添加面板、工具栏、链接等带输入框的面板）收起时滑出屏幕下沿，下面的遮罩一起淡掉。做法见 `shot.rs`：GPUI 只画当前状态，离开的东西是趁它还在屏幕上拍下的原生快照。
- **打字触发的「/」菜单跟着光标所在的行，但占满屏宽。** 它不做成底部面板：面板会盖住正在打的那一行，就没法边打边筛了。
- **带输入框的面板停在键盘上方。** 链接、公式、代码语言的面板占满屏宽，贴在键盘上沿；链接面板的输入框和「确认」是 44pt，按钮单独一行。选中单元格时的表格工具栏和文字的工具栏一样停在底部、可横向滑动。
- **没有悬停手柄，整块的操作在右边。** 页边只有 20pt，块左边的手柄放不下。编辑时，光标所在的块第一行右侧有一个拖动标记（两道短横）：点它选中整块并升起块菜单，按住它拖动就是排序。没在编辑时（键盘收着），长按一个块直接把它提起来拖；编辑时长按仍是选词。落点、拖着的影子和拖到边上自动滚动用的是桌面版原有的那一套。添加和块菜单在键盘工具条上也有。
- **选文件、存文件用系统的面板。** 导入在浏览页右上角「…」的菜单里（Markdown 文件、文件夹、DocxXML），导到当前的文件夹。「下载为 Markdown」、图片和附件的「下载」先写到沙盒的临时目录，再弹出系统的「存储到」。插入图片和上传封面只让选图片。
- **选区工具栏停在键盘上方。** 点编辑菜单的「格式」后，工具栏占满屏宽停在底部，按钮 40pt，可横向滑动；类型、颜色、更多的下拉是它上方的整宽面板，色块 40pt。
- **从主页开始。** 左缘右滑：文档、文件夹和回收站回主页，设置返回。没有玻璃的系统上没有标签栏，侧栏仍是从左侧滑出的抽屉，主页左缘右滑拉出它。
- **安全区。** 顶栏在状态栏之下，内容避开 Home 指示条；键盘弹出时正文和浮层都收在键盘上方。状态栏的字跟着应用的深浅色走。
- **键盘工具条。** 撤销、重做、添加块、块菜单、标题、列表、缩进、粗体等，只派发编辑器已有的动作。右端的按钮收起键盘。
- **编辑菜单。** 长按选词（可继续拖动）、双击选词，或在光标上再点一下，弹出系统的编辑菜单（剪切 / 复制 / 粘贴 / 全选，和别的应用里是同一条，位置和收起由系统管）；「格式」换成原有的选区工具栏。阅读模式下长按复制的代码已接上，尚未在模拟器里验证。
- **长按当右键。** 侧栏的行、主页的卡片、回收站的行，原本挂在右键上的菜单都由长按打开。
- **目录** 的按钮在顶栏，列表是临时浮层，选了标题就收起，不记进设置。
- 搜索、「移动到」、文档信息等对话框按屏幕宽度重排；回收站在窄屏不显示「位置」一列。页边距在窄屏是 20pt。

文档库在应用沙盒的 `Documents/Quiet.md`，首次启动放入「开始指南」。编辑后按桌面的节奏保存，进入后台时立即保存。

### 原生玻璃

iOS 上 GPUI 的 Metal 画面是不透明的，桌面版「玻璃垫在画面下面」的做法用不了。这里反过来：`glass.rs` 把 `UIVisualEffectView`（`UIGlassEffect`）盖在 Metal 视图上面，折射的就是 GPUI 画的内容。玻璃和系统菜单的按钮放在 Metal 视图旁边、盖在它上面的一层透明视图里（`shot::overlay`，点到空处时它自己不接，触摸照旧落到 GPUI），不是 Metal 视图的子视图：退场的快照只拍 Metal 视图，不能把玻璃也拍进去。由此有三条约束：

- **玻璃上的东西必须是原生视图。** GPUI 画不到玻璃上面，所以图标是把资源里同一份 SVG 用 resvg 画成模板图交给 `UIImageView`，文字是 `UILabel`（系统字体）。带 GPUI 文字或会滚动的内容不适合放玻璃。玻璃菜单是一块作底的圆角玻璃（`glass::panel`）加几行没有自己玻璃的原生图标和字（`glass::row`）。
- **点击仍归 GPUI。** 原生视图不接触摸，点击落到下面同一位置的 GPUI 元素；GPUI 元素里放一个 `glass::pane(...)` 占位，把自己的位置交给同名的玻璃。
- **玻璃永远在最上层。** 抽屉、面板、对话框出现时由 `glass::begin` 全部藏起；元素不在画面里的玻璃在下一帧藏起。

**系统菜单**（`menu.rs`）是另一种叠法：出现时的变形、按住滑动时跟手的高亮都是系统做的，自己拼的玻璃做不出来。那个透明按钮自己接触摸，那一小块的点击不经过 GPUI；菜单项的回调来自系统，先排进 GPUI 的主线程队列，再进工作区（`ios::menu_action`）。菜单的样子、朝哪边弹、各项的顺序都由系统定，图标用 SF Symbols。首页「文件夹」一栏的「…」和浏览页右上角的「…」是这样做的；后者连按钮本身也是系统的玻璃钮，菜单从它里面变出来。

**自己接触摸的玻璃。** 底部的标签栏和新建按钮打开了玻璃的「可交互」（按下时的拉伸和高光是系统的），上面盖着透明的原生按钮接点击，同样经 `ios::menu_action` 回到工作区。这两处的点击不经过 GPUI。

类名和选择子都在运行时查找，没有 `UIGlassEffect` 的系统上 `glass::supported()` 为假。设 `SIMCTL_CHILD_QUIET_MD_IOS_NO_GLASS=1` 可以在新系统上看旧系统的版式。

### 还没有的

- **从相册选图。** 插入图片和上传封面走的是「文件」，不是相册。「下载为 PDF」和打印在 iOS 上没有。
- 导入文件夹时文件夹留在原地读（向系统要了访问权后不再交还）；其余选中的文件由系统拷进沙盒的临时目录再读。
- 多窗口、快速笔记、打印、自动更新在 iOS 上没有入口。
- 「开始指南」里那张四列的表格，第二、三列之间有一道约 10pt 的缝，原因还没查。
- 依赖悬停或拖动的控件还没有触屏替代：表格的行列手柄、图片缩放、侧栏和主页的拖动排序。
- **插入的图片、附件和上传的封面，应用更新后会显示「文件不存在」。** 文档里记的是文件的绝对路径，而 iOS 每次安装或更新应用，沙盒目录的路径都会变（文件还在，路径对不上了）。「开始指南」里的图用的是相对路径，不受影响。还没有修。
- 主页的标签行、设置页的控件仍是桌面尺寸。「…」菜单里「下载为」「更多」的子菜单、导出 Markdown 的设置对话框也还是桌面的版式（对话框里第二个选项在手机上被裁掉）。
- 表格工具栏、公式和代码语言面板的手机版式只编译过，还没有在模拟器或真机上看过；触屏怎么选中多个单元格也还没有做。
- **过渡还差的。** 往里走时只有新页滑入，旧页不向左退（视差只在返回时有）。顶上的玻璃钮不在两页之间变形：返回时离开那一页的淡出，新页的等旧页走完再淡入。底部面板不能拖着收（没有抽屉式的抓手），工具栏上方的下拉（类型、颜色、更多）出现时没有动画。快照和 Metal 新的一帧是两条路上屏的，模拟器上没看到闪，真机上要确认。
- 抽屉不能左滑收起。
- 键盘工具条和选区工具栏还不是玻璃。回收站和设置页仍是固定的标题栏，内容没有顶到屏幕上沿。
- 文件夹页里没有上级路径（只有回上一级的按钮）；在这个文件夹里新建文档用底部的「+」。首页（几个去处的那一页）没有「导入」，要先进「所有文档」或某个文件夹。
- 主页的卡片是等高的两列，没有做成 Craft 那样高低错落的瀑布流（网格用的是等高行的虚拟列表）。
- 文件夹卡片上悬停才出现的「新建」「更多」两个按钮也不放，对应的操作在长按菜单里。
- 悬浮顶栏比桌面少了两样：文档标题和它前面的上级路径（原来点路径可以去上级文件夹，现在只能返回主页再进）。主页工具行的「批量管理」和批量管理里的「退出」在手机上只剩图标，没有文字；列表视图只留标题和一列时间。
- 目录按钮要等编辑器画过一帧才知道文档有没有标题：在实心顶栏的版式里，刚打开文档时它可能晚一次重绘才出现。
- 公式、链接、代码语言等带输入框的编辑器浮层，没有逐个在键盘弹出时检查过位置。

## 改代码

`port.patch` 不手改。先建一份可编辑的源码树，在里面改，再重新生成补丁：

```sh
prototypes/ios/dev-tree.sh      # target/ios/dev = 当前桌面源码 + port.patch
# 编辑 target/ios/dev/src/…；新的 iOS 代码尽量写在本目录的 .rs 里
prototypes/ios/make-patch.sh    # 由 target/ios/dev 重新生成 port.patch
prototypes/ios/run-simulator.sh "$device"
```

桌面的 `src/` 变了之后，补丁可能打不上：删掉 `target/ios/dev` 重新建，按报错的位置修。

`Cargo.toml` 关掉了 `gpui-pre` 的调试断言：桌面代码会对同一元素再次设置 hover / active 样式（后设的生效），上游只在调试构建里对此 panic。

调试构建没有优化，换页和滚动会明显发涩；要看真实的流畅度，用 `cargo build --release` 的构建。

## 在 Apple Silicon 模拟器运行

需要 Xcode、已安装的 iOS Simulator 运行时，以及仓库指定的 Rust 工具链。

```sh
rustup target add --toolchain 1.99.1 aarch64-apple-ios-sim
device=$(xcrun simctl create 'Quiet.md Prototype' \
  com.apple.CoreSimulator.SimDeviceType.iPhone-18-Pro \
  com.apple.CoreSimulator.SimRuntime.iOS-27-0)
xcrun simctl boot "$device"
xcrun simctl bootstatus "$device" -b
prototypes/ios/run-simulator.sh "$device"
```

省略设备参数时，脚本只构建并签名 `target/ios/Quiet.md Prototype.app`。原型使用独立的 bundle ID，文档库在模拟器的沙盒里。测试时用 `SIMCTL_CHILD_QUIET_MD_HOME` 指定别的文档库；相对路径落在沙盒的临时目录。

## 验证

安装 XcodeGen 后，在上面的专用 iPhone 18 Pro 模拟器运行以下命令。测试按该型号的屏幕坐标操作，要求软件键盘可见。

```sh
prototypes/ios/verify-simulator.sh "$device"
```

测试用 `QUIET_MD_IOS_SAMPLE` 让文档库只放 [sample.xml](sample.xml) 并直接打开它，在独立的临时文档库里长按拖动、双击选中 `Quiet`、点击拼音键盘输入 `nihao`，再选择「你好」。`QUIET_MD_IOS_VERIFY_BACKGROUND` 关掉定时保存，测试按 Home 后由脚本核对磁盘中的文字、合并单元格和 LaTeX 源码，然后重启并截图。可在生成的 `Result.xcresult` 查看触屏选区、拼音候选和提交后的截图。
